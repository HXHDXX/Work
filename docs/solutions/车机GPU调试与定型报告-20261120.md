# 车机显示问题攻坚与系统定型报告（2026-11-20）

## 一、结论

车机"整机卡死"与"地图闪烁"两大顽疾今日全部定位并解决，系统配置定型、可复装上产；唯一遗留为飞腾 GPU 驱动内核缺陷（偶发秒级卡顿后自愈），对厂商的工单证据链已备齐，已经发给对接厂商。

## 二、主要成果

1. **两类"卡死"分别破案**：一类是麒麟系统自带节能组件在无人操作时误判空闲、切断系统盘致整机冻结（拆除＋策略加固根治）；一类是 GPU 驱动"自动恢复"名不副实、恢复后永久阻塞（更换配套驱动版本根治）。
2. **地图闪烁零代码解决**：真凶为系统节能组件对显示数据同步链路的干扰（同一组件亦是卡死元凶），拆除并锁定高性能策略后地图默认渲染模式即完全清洁（两轮重启复验），未改动任何应用代码。
3. **厂商工单无法推脱的证据链**：使用国际开源标准工具在"无任何应用在场"条件下复现 GPU 挂死，配合内核日志自认记录，彻底堵死"应用自身问题"的推诿口径。
4. **量产可复制资产**：驱动安装包×7（离线可装）、车机电源策略服务×1（开机自启）、系统救援手册（三级恢复手段），新机 30 分钟可复现定型态。

## 三、攻坚历程（一日全链路）

- **上午**：导航压测连续触发卡死，部署每秒级监控＋内核取证，先后识别"GPU 挂死→假恢复→整机锁死"完整链条；
- **中午**：为找到与内核匹配的用户态驱动，梳理官方源全部 32 个历史版本谱系、与 7 个内核逐一指纹比对，锁定"同代配套"规律；多数历史版本已被官方渠道清退，逐一探测后仅存的 2 个可得版本经 5 组合实测交叉验证选定目标，随后完成三轮换装与升降级回滚验证（含版本串实证确认）；
- **下午**：搭建跨平台录制/重放实验环境（x86 录制、车机重放），实现无应用复现；闪烁问题经"同应用×三种驱动环境"对照实验闭环归因；
- **晚间**：致命卡死真凶意外落网（系统节能组件掐断硬盘数据链路——与 GPU 毫无关系）；期间遭遇显示引擎深度楔死事故，形成三级救援手册并验证。
